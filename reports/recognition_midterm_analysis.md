## 1. 当前性能 vs 预期

| 指标 | 值 | 说明 |
|------|-----|------|
| **Top1** | **12.30%** | 3483类验证集 |
| **Top5** | **21.85%** | |
| 随机基线 | 0.0287% (1/3483) | |
| **相对随机提升** | **428x** | |
| HUST-OBC (1016类) | 79.3% | 参考：更小分类空间 |

**判断**：对于3483类从头训练的模型，12.3%处于合理范围但偏低。HUST-OBC在1016类上达到79%，按比例外推，3483类理论上可达50-60%。当前12.3%说明训练策略有优化空间。

## 2. Shared vs Competition-Only

| 类别分组 | 样本数 | Top1 |
|----------|--------|------|
| Shared (与HUST重叠 571类) | 3,771 | **10.71%** |
| Competition-Only (2912类) | 5,239 | **13.44%** |

**Competition-only类反而高出2.7个百分点。**

原因分析：
1. **HUST预训练权重来自从零训练的backbone**（无ImageNet），特征质量有限
2. **Domain shift**：HUST数据是GuoXueDaShi网站截图，Competition是拓片YOLO裁剪，视觉差异大
3. **Shared类是高频甲骨文字符**（乍、子、王、用…），彼此高度相似，分类难度更大
4. Competition-only包含更多中频独特字符，辨识度更高
5. **类别数不匹配**：HUST 1016类权重直接复制到Competition 3483类头部的571个位置，破坏了Xavier初始化的分布特性

**结论：当前HUST预训练策略对Competition任务没有正面贡献。**

## 3. 按样本量分组准确率

| 分组 | 样本阈值 | 类别数 | 验证样本 | Top1 |
|------|---------|--------|---------|------|
| Head | >50 | 228 | 6,225 | 11.26% |
| **Medium** | **10-50** | **436** | **1,649** | **18.92%** |
| Tail | <=5 | 2,322 | 578 | 7.96% |

**Medium类表现最佳(18.9%)，Head类反而不如Medium(11.3%)**。

原因分析：
- **Head类 = 最常见甲骨文**（乍、子、王、用、之、父…），视觉上彼此高度相似
- 混淆矩阵Top1错误：乍→亡(25次)，王→壬(15次)，月→夕(9次)
- 高频字符之间的大量混淆拉低了Head类准确率
- Medium类为中等频率的独特字符，视觉特征更鲜明

## 5. 投影分析

基于E2-E11的Top1增长曲线（幂律拟合 `top1 = 0.0489 × epoch^0.353`）：

| Epoch | 投影Top1 |
|-------|---------|
| 15 (当前) | ~13.5% |
| 30 | 16.3% |
| 50 | 19.5% |
| 80 | 23.0% |
| 120 | 25.8% |

**按当前收敛速度，即使训练到Epoch 80，Top1也仅23%。** 纯交叉熵+Focal Loss的分类训练天花板很低。

## 6. 路线判断

| 选项 | 预期Top1 (E50) | 实现难度 | 评价 |
|------|---------------|---------|------|
| A. 继续当前训练 | ~19% | 零 | 不具竞争力 |
| B. 修改训练策略 | ~35-45% | 低 | 更高LR，更长训练，更强augmentation |
| C. Metric Learning | ~40-50% | 高 | 需要Triplet/SemiHard mining，epoch时间长 |
| **D. ArcFace** | **~45-55%** | 中 | 专为长尾设计，直接替换分类头 |

## 7. 推荐方案：B + D

**ArcFace + 强化训练策略**：

1. **替换Focal Loss为ArcFace**（Additive Angular Margin Loss）
   - 直接在角度空间优化类间距离
   - 天然适合长尾分布
   - 3483类场景下比Focal Loss更有效

2. **放弃HUST预训练权重**
   - Shared类表现不如Competition-only，预训练无正面贡献
   - 改用在ConvNeXt-Tiny ImageNet权重上训练（需要解决网络问题）
   - 或从零训练但加大epoch到80-100

3. **训练配置调整**
   - LR: 1e-3 (当前1e-4太保守)
   - Epochs: 80-100
   - 更强augmentation: RandAugment(m=15)
   - Warmup: 10 epochs
   - Batch Size: 256 (当前VRAM仅0.6GB，可以翻倍)

4. **分类头设计**
   ```
   Backbone → Linear(768, 512) → BatchNorm → ArcFace(512, 3483)
   ```
   先降维到512再ArcFace分类，减少参数量并改善泛化。

## 8. 结论

**不继续当前训练。** 采用ArcFace + ImageNet权重 + 80 epoch路线重新训练，预期Top1可达45-55%。当前12.3%的Top1远低于Competition微调应有的水平，根因是：(1)HUST预训练权重无效，(2)LR过低收敛慢，(3)Focal Loss不适合超多类长尾场景。
