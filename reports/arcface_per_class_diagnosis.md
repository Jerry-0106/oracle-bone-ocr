## 3. 每类训练样本数与准确率关系

| 训练样本数 | 类别数 | 验证样本 | **Top1** | 解读 |
|-----------|:---:|:---:|:---:|------|
| 1 | 1,407 | 165 | **13.33%** | 视觉独特的罕见字 |
| 2–3 | 692 | 259 | **9.65%** ⚠️ | 比 1-sample 更差！ |
| 4–5 | 223 | 154 | 19.48% | |
| 6–10 | 306 | 380 | 22.63% | |
| 11–20 | 190 | 467 | 25.05% | |
| 21–50 | 202 | 1,115 | 27.53% | |
| 51–100 | 109 | 1,432 | 27.58% | |
| **100+** | **119** | **4,793** | **40.00%** | 天花板 |

### 关键发现

1. **"2–3 样本"比"1 样本"更差** (9.65% vs 13.33%)：1-sample 类往往是视觉上独特的罕见异体字（容易被记住），而 2–3 sample 类可能是字形相似的常见字变体（易混淆）
2. **从 6 样本到 100+ 样本，准确率从 22% 缓慢上升到 40%**：数据量增加 16 倍，准确率仅提升 18pp。边际收益严重递减——这不是数据量问题，是**特征容量问题**
3. **100+ 训练样本的类也仅 40%**：即使模型见过每个类 100 次以上，仍然无法可靠区分

## 4. 损失来源分析

| 类别组 | 验证样本 | 准确率 | 错误数 | **占总错误%** |
|------|:---:|:---:|:---:|:---:|
| **Head (>50样本)** | 6,225 (69%) | 37.14% | **3,913** | **69.6%** |
| Medium (10–50) | 1,649 (18%) | 26.68% | 1,209 | 21.5% |
| Tail (≤5) | 578 (6%) | 13.32% | 501 | 8.9% |

### 判断: **A. 头部类别**

**69.6% 的错误来自 Head 类（>50 训练样本）。**

直觉上长尾问题常被视为瓶颈，但数据说了一个不同的故事：

- Tail 类准确率确实极低 (13.3%)，但验证样本总量太小 (578/9010 = 6.4%)
- Head 类准确率虽"较高" (37.1%)，但验证样本占了 69%
- **Head 类的 3,913 个错误是 Tail 类 501 个错误的 7.8 倍**
- **Head 类每提升 1pp 准确率 → 全局 Top1 提升 0.69pp；Tail 类每提升 1pp → 仅 0.064pp。Head 类的改进杠杆是 Tail 类的 10.8 倍**

> 这不是一个"长尾问题"——这是一个**连高频类都学不好的特征质量问题**。

## 5. 为什么 100+ 样本的类仍然只有 40% — 六项逐一检查

### 5.1 输入分辨率 (224×224)

**结论: ❌ 分辨率不足**

实际统计 (随机 100 张图像):

| 统计项 | 值 |
|--------|-----|
| 尺寸范围 | 62×44 ～ 757×844 |
| 平均值 | 250×299 |
| ≥1维 > 224px | **63%** |
| ≥1维 > 384px | **28%** |
| ≥1维 > 512px | **13%** |

63% 的图像在 resize 到 224 时丢失了细节。甲骨文字符的关键区分特征（如"王"vs"壬"仅差一横）在 224px 下可能被压缩到 1–2 像素的差异。训练时 RandomResizedCrop(224, scale=(0.8, 1.0)) 进一步裁剪 80–100% 的图像区域，加剧了信息丢失。

### 5.2 数据增强是否过强

**结论: ⚠️ RandAugment M=9 不适合灰度拓片**

```python
RandAugment(num_ops=2, magnitude=9)
# M=9 包含激进的 ColorJitter/Brightness/Contrast 变换
```

甲骨文拓片是灰度图像。激进的色彩变换会：
- 前景/背景反转 → 改变字形的视觉特征
- 引入训练中不存在的颜色伪影
- 在仅有 15 样本/类的稀疏信号上叠加过度噪声

HUST 预训练用了同样的 RandAugment 但搭配了 Mixup(α=0.2) + CutMix(α=0.2) 作为正则化补偿。ArcFace 阶段**删除了 Mixup/CutMix，但保留了同样强度的 RandAugment**，正则化与信号比失衡。

### 5.3 ArcFace 参数是否合理

**结论: ❌ s=30, m=0.5 对 3,483 类严重不足**

| 参数 | 当前值 | 推荐值 | 差距 |
|------|:---:|:---:|:---:|
| s (scale) | 30 | **64** | 2.1× 不足 |
| m (margin) | 0.5 (28.6°) | **0.7** (40.1°) | 40% 不足 |

**定量分析**:
- s=30 → logit 动态范围受限。3,483 个类之间的角度差异天然微小，s 不够大时 softmax 无法有效放大差异
- m=0.5 → 为每类分配约 28.6° 的隔离区。但 3,483 个类挤在 512 维球面上，平均每类仅约 2.1° 的空间
- 直接证据: 特征空间 gap 从 Linear 的 0.090 → ArcFace 的 0.119（分离比 1.12x→1.14x），说明 margin 推力不足——类间没有被充分推远

### 5.4 Learning Rate 是否过低

**结论: ⚠️ Backbone LR=1e-5 偏保守，但非主因**

```
Backbone LR: 1e-5 (0.1 × base)
Head LR:     1e-4
Cosine:      3 epoch warmup → 57 epoch 衰减至 ~0
```

E52 左右 LR 降到 ~0，E52→E60 完全没有进步（Top1 波动在 32.11–32.18%）。**LR 衰减到 0 的时机过早**，导致模型在仍有学习空间时就停止了有效更新。但即使 LR 更高，ConvNeXt-Tiny 的特征容量也限制了最终收益。

### 5.5 是否出现欠拟合

**结论: ✅ 容量受限的欠拟合 (Capacity-Limited Underfitting)**

| 指标 | E17 | E60 | 趋势 | 判断 |
|------|:---:|:---:|------|------|
| Train Loss | 11.72 | 10.59 | ↓ | 仍在学习 |
| Val Loss | 5.58 | 5.40 | ↓ (缓慢) | 无过拟合 |
| Train Top1 | 14.9% | 20.8% | ↑ | 仍在改善 |
| Val Top1 | 29.3% | 32.2% | ↑ (趋平) | 接近天花板 |

**判断依据**:
1. ✅ Val Loss **全程下降，无一次连续上升** → 排除过拟合
2. ✅ Train Top1 (20.8%) < Val Top1 (32.2%) → ArcFace 训练时 margin 使 train 更难，属于正常行为
3. ⚠️ E52 后 LR≈0，Top1 停滞 → **在现有配置下已达容量上限**
4. ⚠️ 模型仍有学习意愿（train loss 持续下降），但 Val 提升幅度递减

**类比**: ConvNeXt-Tiny 的 768 维特征空间是一个"房间"，要容纳 3,483 个互相保持距离的类原型。"房间"本身不够大:

```
HUST-OBC:   1,016 类 × 49 样本/类 × 768d → 79.3%  ✅ 装得下
Competition: 3,483 类 × 15 样本/类 × 768d → 32.2%  ❌ 装不下
所需容量:   3.4× 类别 → 至少需要 ~1400d 等效特征维度
```

### 5.6 Top5=44.9% 是否说明特征不足

**结论: ✅ 确切证实特征判别力严重不足**

| 指标 | HUST (1016类) | Competition (3483类) |
|------|:---:|:---:|
| Top1 | 79.3% | 32.2% |
| Top5 | 92.6% | 45.0% |
| **Top1→Top5 提升** | **+13.3pp** | **+12.8pp** |

两个数据集的 Top1→Top5 提升幅度相近（~13pp），但绝对水平差距巨大。

**诊断逻辑**:
- **大 Top1-Top5 gap (>30pp)**: 特征有判别力，正确答案在候选集中，但模型不确定 → 可通过调优 softmax/ArcFace 参数改善
- **小 Top1-Top5 gap (<15pp) + 低绝对水平**: **特征本身无法区分这些类** → 正确答案甚至不在 top-5 候选集中超过 55% 的时间

**我们属于后者。** 当模型犯错时，错误答案比正确答案更"自信"。这正是特征容量不足的经典表现。

## 6. 综合诊断

```
                    Overfitting           Underfitting           Capacity-Limited
Train Loss:          ↓↓ fast              → plateau              ↓↓ (still learning)
Val Loss:            ↑ increasing         → plateau              ↓ (very slow)
Train vs Val gap:    large & growing      small & stable         negative (ArcFace artifact)
Top1-Top5 gap:       —                    —                      small (<15pp)

Our model:  ← Capacity-Limited Underfitting
  Train Loss:  ↓↓ (11.7→10.6)     ← 模型仍在努力学习
  Val Loss:    ↓ slow (5.58→5.40) ← 但泛化收益递减
  Top1 plateau: E52-60 frozen     ← 已撞到容量墙
  Top1-Top5 gap: 12.8pp (small)   ← 特征混淆，非不确定
```

**不是经典过拟合，也不是经典欠拟合。** 而是 **特征容量墙 (Feature Capacity Wall)**:
- ConvNeXt-Tiny + s=30 + m=0.5 + 224px 的组合在 3,483 类任务上的表现上限约为 32–34% Top1
- 模型已经撞到了这个墙，无法通过更多 epoch 或微调超参数突破
- **需要结构性改变**（分辨率、backbone、特征维度、margin）才能继续提升

## 7. 理论改进估算

### 7.1 数据驱动的敏感度分析

| 改进目标 | 改进幅度 | 可减少错误 | **新 Top1** |
|------|:---:|:---:|:---:|
| 提升 Head +10pp | 37%→47% | 623 | 39.1% (+6.9pp) |
| 提升 Head +20pp | 37%→57% | 1,245 | 46.0% (+13.8pp) |
| 提升 Tail +50pp | 13%→63% | 289 | 35.4% (+3.2pp) |
| 提升 Med +20pp | 27%→47% | 330 | 35.8% (+3.7pp) |

**Head 类每提升 1pp 准确率，全局 Top1 提升 0.69pp。Tail 类每提升 1pp，全局 Top1 仅提升 0.064pp。Head 类的改进杠杆是 Tail 类的 10.8 倍。**

### 7.2 各技术预期收益

| 技术 | 主要受益群体 | 预期 Top1 提升 | 理由 |
|------|:---:|:---:|------|
| **Focal Loss (γ=2)** | Head+Med 难例 | **+3–5pp** | 让模型聚焦难例。Head 类有大量难例 (37% 准确率) |
| **Class-Balanced Loss** | Tail | **+1–3pp** | Tail 仅占 8.9% 错误，即使翻倍也有限 |
| Weighted Sampler (优化) | Tail | +1–2pp | 已用 sqrt 权重，换线性权重提升有限 |
| Focal + CB 联合 | Head+Tail | +5–8pp | 叠加效果但边际递减 |
| **更强 Backbone (DINOv2)** | **Head 为主** | **+15–25pp** | 解决 70% 错误的正解 |

## 8. 最可能带来 10%+ 绝对 Top1 提升的三个实验

### 🥇 实验一: Backbone 升级 — DINOv2 ViT-B

| 项目 | 值 |
|------|-----|
| **预期 Top1 提升** | **+15–25pp** (32% → 47–57%) |
| 预期训练时间 | 3–4 天 (60 epochs) |
| 风险 | 低 |
| 成功概率 | **80%** |
| 解决的核心问题 | 特征容量 (70% 错误来源) |

**为什么这是最高收益**:
- 768d→768d (ViT-B) 但特征质量质的飞跃：DINOv2 在 142M 图像上预训练
- DINOv2 k-NN (零训练) 已 9.81%，比随机基线好 342× → 有基础判别力，需要微调释放
- 304M 参数 (ViT-L) vs 30M 参数 (ConvNeXt-Tiny) → 10× 容量
- 从零训练 9.81% 到微调 47–57% 的提升轨迹与 ImageNet 上 ViT 的表现一致

**实施**: 替换 backbone 为 `facebook/dinov2-base`，其余训练代码不变。

---

### 🥈 实验二: 分辨率提升 + 强 ArcFace

| 项目 | 值 |
|------|-----|
| **预期 Top1 提升** | **+8–12pp** (32% → 40–44%) |
| 预期训练时间 | 2–3 天 (50 epochs from current ckpt) |
| 风险 | 低 |
| 成功概率 | **75%** |
| 解决的核心问题 | 笔画细节丢失 + 类间分离不足 |

**具体改动**:
```
224 → 384 分辨率 (63% 图像原生 >224px)
s=30 → s=64 (放大 logit 动态范围)
m=0.5 → m=0.7 (将最小类间角度从 28.6° 推到 40.1°)
```

**代价**: BS 需从 128 降到 64（显存 ~1.5GB），12GB VRAM 仍有余量。

---

### 🥉 实验三: 增强策略重设计

| 项目 | 值 |
|------|-----|
| **预期 Top1 提升** | **+5–10pp** (与实验一/二叠加) |
| 预期训练时间 | 2–3 天 |
| 风险 | 中 |
| 成功概率 | **65%** |
| 解决的核心问题 | 增强不适应甲骨文 + 缺少 Mixup/CutMix |

**具体改动**:

```python
# 替换 RandAugment(N=2, M=9) 为甲骨文专用增强:
RandomResizedCrop(384, scale=(0.6, 1.0))
RandomAffine(degrees=5, translate=(0.05, 0.05))    # 拓片变形
RandomPerspective(distortion_scale=0.1, p=0.3)      # 透视
GaussianBlur(kernel_size=(3, 7))                     # 拓片模糊
RandomErasing(p=0.2, scale=(0.02, 0.1))             # 笔画侵蚀
# 不加 ColorJitter, 不加 HorizontalFlip

# 恢复 Mixup(α=0.2) + CutMix(α=0.2) — HUST 预训练中有效 (Top1=79.3%)
```

**为什么**:
- RandAugment M=9 的色彩变换对灰度拓片是噪声
- 物理退化模拟（模糊/侵蚀/变形）更贴合真实数据
- Mixup/CutMix 在 HUST 上验证有效，可平滑决策边界、减少 Head 类间混淆

## 9. 总结

| 问题 | 答案 |
